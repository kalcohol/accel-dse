# npu_dse 工作台布局改版提案（基于 0.27.0 · 仅提案，未改动 `npu_dse/web`）

对照图：`before-1440.png` / `before-1920.png` / `before-mobile-390.png`（现状首屏）↔ `mockup-*.png`（提案）；可交互静态稿 `mockup.html`（零依赖，数值取自真实 `/api/eval` 与 `/api/sweep`：qwen3-32b · hbm_hbm3e_4s · cluster_256t · 2 芯片 · EXAMPLE 能耗占位值）。

## 1. 现状问题清单（1440×900 实测）

| # | 问题 | 证据 |
|---|------|------|
| 1 | **左栏过长，核心参数被挤出首屏** | 左栏高 2343 px，首屏只看到 预设 / 领域 / 系列 / 芯片数；封装、算力、负载均在首屏以下 |
| 2 | **「评估」按钮离得太远，而且其实不需要点** | 按钮在 y≈2407（约 2.7 屏）。实际上每次改参数都会**自动评估**（防抖 280 ms），按钮只是误导 |
| 3 | **自动评估的结果看不到** | 右栏不吸顶。在左栏下方调 能耗 / 校准 时，MetricsCard 已滚出视野，等于盲调 |
| 4 | **右栏下方大片空白** | 右栏高 1014 px，左栏 2343 px，约 1330 px 空白（≈57%） |
| 5 | **对比 / 扫描、A\|B 几乎发现不了** | A\|B 在 y≈2563，对比 / 扫描在 y≈2754（3 屏以下），与当前结果分离 |
| 6 | **信息层级扁平** | 10 张同尺寸指标卡（TTFT 与「芯片数」同权重），能耗卡又另起一节 |
| 7 | **重复信息** | honesty banner 出现两次（顶部 113 px + 假设框）；TP/PP/EP 出现 3 处；A\|B 的两张 kv 卡与 Δ 表内容重复 |
| 8 | **低频参数常驻展开** | 能耗 / 成本 8 项（默认关闭）、校准 3 滑块、算力附加项都常驻左栏 |
| 9 | **反馈位置差** | 错误框在左栏底部；基线 Δ 只在扫描表里出现，KPI 上看不到 |
| 10 | **时间分解只有数字** | 「瓶颈」没有可视化，无法直观看出 计算 vs 访存 的差距 |
| 11 | **可发现性** | 预设只是 3 个 id 按钮，无说明；`?c=` 分享链接已有功能但没有入口；导出按钮在扫描前一直是禁用状态 |
| 12 | **首次加载即 OOM** | 默认 glm-5.3 @ 1 芯片 → 首屏红色「容量不足 OOM」，第一印象差 |
| 13 | **窄屏 / 移动端不可用** | 390 宽时结果从 y≈2825 才开始（3.3 屏） |
| 14 | 小缺陷 | wall 值 `balanced` 未进中文映射（0.27 漏项，显示英文）；series 元数据里的 URL 噪声占 3 行 |

## 2. 新布局结构

```
┌ 顶栏（吸顶）  npu_dse 工作台 v · ●已自动更新 · ⚠假设值·未标定 · ⟳重新评估 · 🔗复制链接 ┐
├ 场景栏（吸顶，2 行）                                                                 │
│  行1 领域[LLM|视频|蛋白质] 系列[▾] │ 存储[HBM|LPDDR][封装▾] 算力[▾] 芯片数[−2+] TP2·PP1·EP1 │
│  行2 批大小 提示长度 上下文长度（随领域切换） dtype 量化 │ 场景预设[▾]  [⚙ 高级参数 · N 项已修改] │
├ 诚信条（1 行，点击 → 「假设与说明」标签页）                                          │
├ KPI 条（7 张）：TTFT · TPOT(+Δ vs 基线) · 瓶颈 · 容量/OOM · 扩展效率·加速比 · 能效「假设」· 成本「假设」 │
├ 标签栏：概览 | 对比 / 扫描 | A|B 对比 | 假设与说明(n)        基线chip [固定基线][固定为A][固定为B] │
└ 标签内容                                                                              │
   概览：[时间分解：堆叠条 + 分项条形（最长=瓶颈）] [硬件与资源 kv 表]                       │
         [本次假设（前 4 条 + 查看全部）]                                                  │
   ≥1680 px：分屏 —— 左侧固定「概览」，右侧显示 对比/扫描 · A|B · 假设 之一（填满 1920 宽屏）  │
右侧抽屉「⚙ 高级参数」（420 px，手风琴分组，每组显示状态：默认 / 已修改）：
   并行(锁定 TP/PP/EP) · 存储几何(手动) · 算力(手动核数) · 校准/覆盖 · 算力附加项 · 能耗/成本「假设」
   ≥1280 px 非模态：主区让位，KPI 保持可见，边调边看；<1280 px 遮罩式；手机端全屏
```

各区域放什么：

- **场景栏**：只放高频参数（领域、系列、封装、算力、芯片数、负载、dtype、量化），1440 宽下两行放下。预设从 3 个按钮改为下拉框，选项里带中文说明。
- **KPI 条**：只放决策指标。峰值 TOPS、有效带宽、利用率、PE、字节数挪到「硬件与资源」表。
- **标签页**：对比 / 扫描和 A\|B 不再堆在页面最底部，与当前结果同处一屏，并沿用当前场景作为扫描基准。

## 3. 交互变化

1. **自动评估显性化**：去掉底部「评估」大按钮，改为顶栏状态胶囊「●已自动更新 · x s 前 / 评估中… / 出错」，旁边保留「⟳ 重新评估」（沿用 `id="btn-eval"`）。评估逻辑沿用现有 `scheduleEval` 防抖，无需新增。
2. **场景栏和 KPI 始终在视野内**（吸顶 + 非模态抽屉），彻底消除「调完参数滚回去看结果」。
3. **「N 项已修改」徽标**：合并现有 `updateOverrideBadge`、`updateAssumedComputeBadge` 和能耗启用状态，挂在 ⚙ 按钮和各手风琴标题上。
4. **基线 Δ 上 KPI**：固定基线后，TPOT / TTFC / 每序列时间 KPI 直接显示 Δ%，扫描表保持不变。
5. **错误就近显示**：评估错误显示在 KPI 条上方的红条（加 toast）；并行乘积 ≠ 芯片数的提示放在场景栏的 TP·PP·EP 标签上。
6. **复制链接**：顶栏按钮把当前 `?c=` URL 写入剪贴板。
7. **对比 / 扫描**：改轴后直接点「运行扫描」；导出按钮放在同一行。（可选，二期）点表格行 → 设为当前场景 / 固定为 A 或 B。
8. **A\|B**：两张头卡只显示「名称 + 配置一行摘要」，下面一张 Δ 表；默认只列有差异的字段，可切换「显示全部」。
9. **窄屏（<640 px）**：场景栏折叠成一行摘要和「编辑场景」按钮（打开全屏抽屉）；KPI 两列；标签页可横向滚动。
10. **默认场景**改为不 OOM 的组合（如 `card-hbm-4stack` + qwen3-32b 或 `series/dense-27b`）。

## 4. 保留 / 删减 / 合并

- **保留**：所有功能，包括预设、手动几何 / 算力、校准、算力附加项、能耗 / 成本、基线、A\|B、扫描（5 轴 + 并行 ×4/×8）、CSV/JSON 导出、`?c=` 深链、领域切换，以及「假设」标记体系。
- **合并**：
  - 两处 honesty 文本 → 顶部 1 行诚信条 +「假设与说明」页全文
  - 10 张指标卡 + 能耗 4 卡 → 7 张 KPI + 1 张「硬件与资源」表
  - A\|B 的 kv 卡 + Δ 表 → 1 张表
  - 「Decode 分解」表 + 瓶颈 → 一张可视化卡（堆叠条 + 分项条形）
- **删减（降级）**：
  - 页脚开发说明 → 移到「假设与说明」底部
  - series 元数据（含 URL）→ 系列下拉的 tooltip，以及「假设与说明」里第 1 条
  - 低频输入项（W/TOPS、存储附加 $/卡）→ 在「能耗 / 成本」手风琴里再折叠一层「更多」
  - 「并行矩阵 ×4 / ×8」两个按钮 → 并入扫描维度「TP/PP」的芯片数子选项（保留按钮 id，隐藏或放进「更多」）

**改动面**

| 文件 | 改动 |

| CHANGELOG、版本 | 更新 |

**测试兼容（必须保留，已逐条核对 `tests/test_conservation.py`）**

- **文本**：`Compare / Sweep`（可放 title）、`MetricsCard`、`npu_dse`、`ASSUMED stub`、`EXAMPLE`、`CAPACITY OOM`

**风险**

1. `?c=` 旧链接必须仍可恢复：字段不变即可，新增 tab 字段为可选。
2. 隐藏的 tab 中元素在 `display:none` 下宽度为 0；柱状图需在切换 tab 后渲染或重算。
3. 吸顶场景栏在 1280 宽下可能折成 3 行，需截图验证；必要时把「负载」行改为可折叠。
4. 版本守卫：测试里 10 处 `startswith("0.27")` 在 bump 到 0.28 时要同步修改。建议届时改为从 `pyproject` / `__version__` 读取或只比较主版本，避免每版都改测试。
5. 纯布局 / 交互改动，不涉及建模；`handcheck` 等守卫测试不受影响。
